# Naming shortlist

The team name should survive a change from returns to fulfilment, procurement or another
commerce workflow. The product name can become specific after the problem is selected.

## Recommended team name

### Parallel Authority

Why it works:

- `Parallel` quietly references Monad's parallel execution and the specialist agents working
  concurrently.
- `Authority` expresses the actual technical problem: deciding which agent may perform which
  action with money and external systems.
- It sounds credible beyond a hackathon and does not lock the team to Shopify or returns.
- It supports a simple line: "We build autonomous systems with authority you can verify."

## Strong alternatives

| Name | Character | Note |
|---|---|---|
| Chain of Agency | Memorable and conceptual | Connects delegated agents with an auditable causal chain |
| Autonomous District | Visual and event-aligned | Fits the Metropolis theme and the 3D operations floor |
| City Limits Labs | Clever and approachable | Refers both to Metropolis and bounded agent permissions |
| Delegation Works | Direct and credible | Strong if delegated authority remains the core primitive |
| Agency Protocol | Technical and serious | Better for infrastructure than a consumer-facing product |
| Parallel Operators | Operational | Good for a multi-agent control-room presentation |
| Mandate District | Connected to prior work | Use carefully so the submission remains clearly new |
| The Delegates | Simple and memorable | Friendly hackathon identity, less distinctive as a company |
| Authority Layer | Infrastructure-first | Describes the technical contribution clearly |
| Agent Borough | Playful | Strong event reference, weaker long-term company identity |

## Names not recommended

- **Bounded Works** — an AI/software business already uses this name.
- **Chain of Command** — memorable but extremely common and unnecessarily military.
- **Agentopolis** — obvious hackathon wordplay but difficult to take seriously afterward.
- **Monad Agents** — depends on another organization's brand and says nothing about the work.
- **ReturnPilot** as the team name — ties the team to an idea that has not been selected.

## Product-title directions after finalization

If the project is autonomous returns:

- ReturnPilot — clearest, though not highly distinctive
- AfterOrder — broader post-purchase operations framing
- Resolve Commerce — outcome-oriented
- ReverseOps — operational and specific to reverse logistics

If the project is autonomous commerce operations:

- Commerce Command
- Delegated Commerce
- StorePilot
- OperatorOS

If the project is the authorization infrastructure itself:

- Delegation Chain
- Mandate Protocol
- Authority Graph
- ScopeChain

## Current naming recommendation

Use **Parallel Authority** as the team name. Do not lock the project title until the workflow
passes the finalization gate. If ReturnPilot wins, consider **AfterOrder by Parallel Authority**
as the more durable product framing.

Before public launch, perform a proper trademark, domain, package-registry and app-store check.
This shortlist is naming direction, not legal clearance.
