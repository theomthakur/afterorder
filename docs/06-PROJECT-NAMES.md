# Project-name shortlist

The project name should survive a reasonable refinement of the workflow while still telling a
judge what part of commerce the product owns. It should not lead with blockchain terminology:
Monad is the enabling infrastructure, while the outcome is the product.

## Recommended project name

# AfterOrder

**Tagline:** Autonomous post-purchase operations, governed on Monad.

Why it works:

- It identifies the neglected part of commerce after checkout: fulfilment exceptions, returns,
  replacements, refunds, shipping and reconciliation.
- It remains valid if the MVP narrows to returns or changes to another post-purchase exception.
- It is short, pronounceable and understandable without crypto vocabulary.
- It creates a clean demonstration opening: "Shopify handles the order. AfterOrder handles
  everything that goes wrong after it."
- It can grow beyond a single hackathon workflow.

If the final scope is specifically returns, use:

> **AfterOrder — autonomous return resolution for Shopify**

If the final scope is broader exception handling, use:

> **AfterOrder — the autonomous control plane for post-purchase commerce**

## Strong alternatives

| Rank | Name | Best fit | Assessment |
|---:|---|---|---|
| 2 | OrderRelay | Multi-agent handoffs across Shopify, carriers and payments | Clear movement between systems; slightly logistics-heavy |
| 3 | Resolve Commerce | Returns and exception resolution | Strong outcome, but less distinctive |
| 4 | LoopComplete | End-to-end autonomous execution | Captures closing the operational loop; needs a descriptive tagline |
| 5 | OrderGuard | Governed autonomous actions | Strong for trust and authority; sounds more defensive than agentic |
| 6 | ReverseOps | Returns and reverse logistics | Excellent if the product stays strictly focused on returns |
| 7 | Commerce Command | Broad multi-agent operations | Fits the 3D control room but sounds like a dashboard |
| 8 | Delegated Commerce | Agent authority across commerce systems | Technically accurate but reads like a category, not a product |
| 9 | Finality Commerce | Monad settlement plus completed workflows | Clever for crypto judges, less natural for merchants |
| 10 | ReturnPilot | Autonomous returns | Immediately clear but narrow and uses the crowded `Pilot` suffix |

## Names removed after checking

- **ReturnGrid** — already used by a return-logistics platform.
- **ResolveGrid** — already used by an agentic field-service company.
- **Orderline** — already used by commerce and AI-ordering products.
- **Bounded Works** — already used by an AI/software business.
- **StorePilot** — too broad and sounds like another Shopify dashboard.
- **Agentopolis** — event wordplay rather than a durable product identity.
- **Chain of Command** — common, military and centered on the mechanism instead of the buyer.

## Decision

Use **AfterOrder** as the leading project name while refining the problem. Do not create the
portal entry until we settle whether the submitted MVP is return resolution or broader
post-purchase exception recovery; that choice changes the subtitle and project description,
even though the main name can remain the same.

Before public launch, perform proper trademark, domain, package-registry and app-store checks.
The initial collision search is not legal clearance.
